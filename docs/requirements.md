# HealthBridge 要件定義

## 1. 文書の位置づけ

本書では、MVPの要件と、現在のモックUIで確認できる範囲を分けて記載します。

- 参照資料：Googleドキュメント「【Docs】体調管理・共有アプリ」の「要件定義・技術選定 v2（再レビュー用）」「画面設計 v2（再レビュー用）」「DB設計v2」「API設計v2」「2026.09.17MTG」
- 資料参照日：2026年9月18日
- 画面例：ローカルの最新版を起動し、モックデータの描画完了後に撮影

v2資料にはレビュー前の案も残っているため、第2回レビュー後の決定、Issue #110 / #112、現在のコードと照合しています。

## 2. 開発背景・解決したい課題

### 従業員側

体調を定期的に記録・可視化し、本人が変化を振り返ることで、セルフケアや必要な配慮・サポートの相談につなげやすくすることを目指します。

### 管理者側

担当従業員の体調記録を一覧・履歴から確認し、注意が必要な従業員や未入力の従業員を把握しやすくすることで、声かけや配慮を検討するための情報を提供します。

## 3. 対象ユーザー

初期運用は従業員10名程度の小規模組織を想定し、employee（従業員）とmanager（管理者）の2種類を対象とします。大規模組織向けの上位権限、部署・役職情報は将来検討です。

## 4. MVP機能要件と現在の実装状態

画面上の操作ができても、サーバー側の業務処理が完成したことは意味しません。現在のログイン、権限制御、作成・更新・無効化・担当変更、体調記録はモックUI／ブラウザ内状態です。

## 5. 主な業務ルール

> 以下は運用開始前のため仮に定めたルールです。実装・運用前に再確認します。

### 5.1 体調記録

- 体調は「とても良好」「良好」「普通」「注意」「悪化」の5段階とし、「普通」をグラフ中央に置く
- 1日につき出勤時・退勤時の2回を別レコードとして記録する
- コメントを必須とする
- 同一employee・同一日・同一timingは1件だけとし、初期MVPでは入力後の上書きを行わない
- employeeは本人の体調だけを入力し、managerによる代理入力は行わない

### 5.2 未入力

- 未入力は体調状態として保存せず、対象レコードの不存在から判断する
- 一覧の「未入力」は、指定日の出勤時記録が存在しないemployeeを対象とする
- 出勤時が未入力でも退勤時は入力でき、退勤時だけが未入力の場合は一覧の「未入力」絞り込み対象にしない
- グラフは欠測値そのものを描画せず、前後に記録がある欠測区間だけ点線で結ぶ

### 5.3 担当関係・アカウント

- 1人のemployeeへ現在の担当managerを1人設定する
- managerは自身の担当employeeだけを参照・更新できる設計とし、API側でも検証する
- employee作成時は、作成したmanagerを初期担当者とする
- 担当変更後もemployeeアカウントと過去の体調記録を保持する
- employeeの利用停止は物理削除せず無効化し、過去の記録を保持する
- メールアドレスはユーザー間で重複させない

## 6. 現在の完成範囲とMVP後の候補

### 6.1 現在の完成範囲

- フロントエンド：モックUIと主要操作フロー
- バックエンド：Go / GORMのPostgreSQL接続、標準ライブラリHTTPサーバー、`GET /health`
- 未完成：実認証、サーバー側認可、業務API、DBモデル／マイグレーション、DB永続化、フロントエンドAPI接続、バックエンド公開

### 6.2 MVP後・将来検討

- チーム全体の体調変化の傾向を分析
- 年間等の長期間グラフ
- 未入力メール通知
- 体調記録の修正
- 担当manager変更履歴
- 無効化アカウントの保持期間と自動削除
- 大規模組織向けの上位権限、部署・役職情報
- 従業員数増加時の一覧検索
- 同じ体調が続く場合の支援方法や、改善要因を把握する運用

| 分類 | 要件 | 現状 |

| 対応端末 | PC・スマートフォンで利用できる | レスポンシブUIを実装。月グラフの狭幅表示を確認済み |
| 認証・認可 | employee本人、managerの担当範囲をサーバーで制御する | 未実装 |

| 保守性 | Docker Composeで開発環境を構築できる | 構成済み |
| 品質 | ビルド・バックエンドテストをCIで自動実行する | CI未実装 |
| 動作環境 | Chrome・Edgeで動作する | 今回はChromiumで確認。Edge実機未確認 |
| データ安全性 | デモに実在人物の個人・体調情報を使用しない | 架空のデモ名・データを使用 |
