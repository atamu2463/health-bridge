# HealthBridge レビュー・改善履歴

## 1. このドキュメントについて

HealthBridgeでは、実装を先に進めるのではなく、利用者の課題や運用を確認しながら要件・画面設計を改善することを重視しています。

本ドキュメントでは、就労移行支援事業所のスタッフによるレビューで得たフィードバックと、それを要件・画面設計へどのように反映したかを記録します。

レビュー結果を残すことで、仕様変更の理由を後から確認できるようにするとともに、要件・設計・実装のつながりを明確にすることを目的とします。

## 2. 第1回スタッフレビュー

### 2.1 実施概要

フロントエンドの画面プロトタイプを使用し、HealthBridgeの利用方法や必要な機能について、就労移行支援事業所のスタッフからフィードバックを受けました。

初期案を完成仕様として扱うのではなく、実際の支援・管理を想定した場合に必要な情報や操作を確認し、その後の要件・画面設計を見直すために実施しました。

### 2.2 主なフィードバック

第1回レビューでは、主に以下の観点から要望・意見を確認しました。

- 従業員の体調を1日1回ではなく、出勤時・退勤時に分けて把握できること
- 体調を段階的に記録し、コメントとあわせて確認できること
- 管理者が担当従業員の体調を日付ごとに一覧で確認できること
- 体調に注意が必要な従業員や、体調を入力していない従業員を把握しやすくすること
- 従業員ごとの体調履歴や登録情報を確認・管理できること

### 2.3 要件・画面への反映

第1回レビュー後、フィードバックをもとに要件と画面構成を見直しました。

| フィードバック・課題 | 反映内容 |
| --- | --- |
| 1日の中での体調変化も確認したい | 出勤時・退勤時の1日2回、体調を記録する仕様へ変更 |
| 体調の程度を分かりやすく記録したい | 5段階の体調評価とコメントを記録する画面を作成 |
| 複数の従業員の状況を把握したい | 管理者向けに日付別の担当従業員一覧を作成 |
| 注意が必要な従業員を見つけやすくしたい | 「注意」「悪化」による絞り込みを追加 |
| 入力していない従業員も把握したい | 「未入力」による絞り込みを追加 |
| 個人の状況を詳しく確認したい | 従業員ごとの体調履歴・グラフ・登録情報を確認する画面を作成 |
| 利用しなくなったアカウントも適切に扱いたい | 従業員情報の編集と、データを保持したままアカウントを無効化する仕様を追加 |

これらの変更を反映した画面プロトタイプを作成し、第2回スタッフレビューで再確認することとしました。

## 3. 第2回スタッフレビュー

### 3.1 実施目的

第1回スタッフレビューのフィードバックを反映した画面プロトタイプを使用し、以下の2点を確認しました。

1. 第1回レビューで得た要望を、意図どおり機能・画面へ反映できているか
2. 現在の要件のうち、企業提出版のMVPに含める範囲をどのように整理するか

レビュー後は、得られたフィードバックを要件・DB・API設計へ反映したうえで、Go / PostgreSQLによるバックエンド実装を進める方針としました。

### 3.2 確認事項

レビュー実施前は、特に以下の点を確認する予定でした。共有メモに個別の結論の記載がない項目は、共有メモだけでは承認・確定状況までは確認できません。

| 確認項目 | 確認したい内容 | 結果 |
| --- | --- | --- |
| 5段階の体調評価 | 「とても良好・良好・普通・注意・悪化」の名称で分かりやすいか | 共有メモに個別の結論の記載なし |
| 「未入力」の定義 | 出勤時の体調記録がない状態を「未入力」として扱ってよいか | 共有メモに個別の結論の記載なし |
| 管理者アカウント登録 | 管理者自身がアカウントを登録する現在の方式で問題ないか | 共有メモに個別の結論の記載なし |
| 担当管理者の変更 | 従業員の担当管理者を変更する機能をMVPに含める必要があるか | 共有メモに個別の結論の記載なし |
| チーム体調傾向 | 1か月単位でチーム全体の体調傾向を確認する機能をMVPに含める必要があるか | 企業提出版のMVPから除外 |

年間グラフ、未入力時のメール通知、無効化したアカウントの自動削除などは、MVPには含めず、将来の拡張候補として扱います。

### 3.3 レビュー結果

2026年9月17日に第2回スタッフレビューを実施しました。初期運用は従業員10名程度の組織を想定しています。

#### 決定

- チーム体調傾向機能は企業提出前に外し、MVP対象外とする。
- それ以外の機能は、要望から大きく外れていない

共有メモだけでは、各仕様の個別の承認・確定状況までは確認できません。

#### 改善・検討候補（本対応には含めない）

- 出勤時・退勤時のグラフを異なる色にする
- 欠測区間だけ点線で接続する
- 出勤時／退勤時／両方の表示を切り替える
- 同じ体調が続く場合の支援方法や、改善要因を把握する運用を検討する
- 大規模組織向けの上位権限、部署・役職情報を検討する
- 従業員数が増加した場合の検索を検討する
- 将来のチーム集計で、特定の個人への偏りを確認する方法を検討する

## 4. 今後の反映方針

第2回スタッフレビューで得たフィードバックについて、バックエンド実装へ影響する内容を優先して要件・設計へ反映します。

チーム体調傾向機能は企業提出版の画面と導線から除外し、DB構造はこの機能を外すためだけには変更しません。共有メモに個別の結論の記載がない仕様は、必要な確認を行いながら要件定義、DB設計、API設計を更新します。

画面表示や操作性に関する改善のうち、バックエンド実装を進めるうえで影響しないものについては、MVPの実装を止めず、今後の改善項目として管理します。
